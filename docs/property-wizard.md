# Add property

City staff and brokers use the same five-step submission form: Basics, Area & location, Site evidence, Surroundings, and Review. They share field validation and request construction. Broker ownership and CICTO review permissions remain enforced by the server. The form also edits existing listings and preserves historical area and land-use records.

Basics requires a property name and retains the property categories and availability choices. Asking price, description, photo, and contact details are optional. An omitted asking price is stored as zero for compatibility with the existing schema; it is not a valuation. Save & exit saves a draft in this browser, scoped to the signed-in user and listing. Progress also saves locally when moving between steps. File selections must be chosen again after reopening a draft. Submit listing writes to the server and removes that local draft.

Area & location offers three choices: enter an area size, pin an exact location, or draw a plot. A positive area OR valid latitude and longitude is sufficient; both can also be provided. Barangay is optional. A lone or invalid coordinate is rejected. Drawing uses locally bundled Leaflet-Geoman 2.18.0 and Turf 7.2.0; staff can draw, edit, undo, and reset one closed parcel polygon. The server independently validates the simple WGS84 polygon and recalculates its square-meter estimate.

Manually entered area is labeled Declared area or Survey / property record using `parcel.areaMethod`. It remains separate from `parcel.estimatedAreaSqm`; the entered area takes precedence when both exist. The historical `parcel.surveyAreaSqm` key stores the entered measurement for compatibility. Unknown coordinates and unknown area remain database NULL and are returned as NULL, with `hasExactLocation` and `areaKnown` flags. The system does not assign a city-center location or a default 500 m² measurement. Price per m² is unavailable without area; BIR reference total remains pending until area is known. Area-only listings retain pending spatial assessment.

Site evidence and Surroundings are optional. Skip optional details goes directly to Review after the essentials are valid. A surroundings reference point is not required for submission; when the radar is used, it can derive its reference from the exact property pin or a drawn parcel. A pin-based hazard result covers that point only, not an unrecorded parcel footprint. Hazard findings and assessment justifications are collapsed initially so the form stays focused.

Road frontage, surface, utilities, dated BIR references, environmental references, and site observations are recorded facts. They do not replace authoritative source evidence or approved scoring rules. The seven original criterion weights remain 20/20/20/10/15/10/5. Each missing criterion has a concrete next action. Land-use and CLUP references continue using the existing property fields.

Evidence files accept up to four total JPG, PNG, WEBP, or PDF attachments, each at most 5 MB. The server screens actual MIME, size, signatures, and basic file structure. Images receive additional decoding checks if GD is installed; structural checks are not a complete document or image parser. Files are stored privately under `data/property-evidence`. Staff download them through `api/property-evidence.php`, which checks the property and attachment ID. Public, investor, and broker property responses omit attachment metadata, including save and archive responses. New staged files are discarded if persistence fails before commit. Stored attachment paths cannot be supplied by the browser.

`api/parcel-context.php` exposes configured, verified and fingerprint-checked flood, fault, and road geometry. Missing data displays **Not assessed**. Whole-parcel flood intersection and fault-buffer intersection use Turf. The configuration in `app/assessment-sources.php` must provide verified sources and their coverage, source reference, and date. Set `parcel_context.fault_buffer.meters`, `approved: true`, and the office's `approval_reference` only after the review threshold is approved. A no-overlap finding requires complete source coverage containing the entire parcel. It is not an official clearance.

The surroundings radar stores a labeled reference point. Parcel center is the default; choosing property entrance requires placing or dragging its pin. Distinct mapped establishments are counted using geographic distance within 500 meters, and road features are checked against the search circle. Competitor and complementary roles use an explicit business-type mapping; unclassified records are excluded and reported. The current locator inventory has limited coverage. Missing road or establishment inventories display Not assessed instead of inferred zero counts. Proximity does not establish demand or legal road access.

Review has assessment and investor preview tabs. Approved, complete business profiles can produce up to three eligible business fit results, with criterion ratings, weights, reasons, and concerns. The shipped profiles and authoritative assessment sources are unapproved/unconfigured, so real scores and business matches remain pending. See [business preview configuration](property-business-preview.md). Illustration scores from the reference screenshots are not saved as city evidence.

The property details page uses Inter body text and a red italic Poppins property heading. Both fonts are loaded locally for the property interface and printed report; Poppins SemiBold Italic is distributed under the included `assets/fonts/poppins-OFL.txt` license. Overview, contact, location, and score summaries appear first; detailed evidence and calculations expand on demand. Printing expands all report disclosures, includes property information and source evidence, and restores the previous screen state afterward. The report shows each MCE rating × weight ÷ 100 contribution, MCE rounded to one decimal, and base IAI = round(MCE × 0.60 + economic viability × 0.20 + infrastructure readiness × 0.20, 1). Pending criteria remain pending and prevent totals. Proposed-business incentive adjustments are separate from this base IAI.

Admin Manage controls set Available, Unavailable, or Availed without changing review state. Delete moves a listing to Recently deleted and retains its evidence, inquiries, due diligence, and audit history. Restore returns it to pending review before publication. Public catalogue, showcase, and ranks exclude deleted and unavailable/availed listings. Brokers retain the existing ability to archive their own listings; administrative deletion and restoration require city management permission.

Integration checks use isolated temporary MySQL databases. Browser QA exercises both roles, area-only and location-only submissions, validation, drawing, existing parcels, shared FormData fields, printing, and mobile layouts without creating catalogue listings.
