# Add property

City staff and brokers use the same four-step submission form: Basic information, Location & boundary, Assessment, and Review. They share field validation and request construction. Broker ownership and CICTO review permissions remain enforced by the server. The form also edits existing listings and preserves historical area and land-use records.

The editor keeps the four-step navigation and footer visible while its content scrolls. The listing preview uses a muted background; supporting evidence and hazard details expand on demand. Pin and boundary tools appear above the location map. Small screens retain all four step labels and the same navigation actions.

Basics shows the property name, type, classifications, purpose, and asking price. One checkbox group accepts all applicable classifications; the first retained selection remains the primary value for API compatibility. Land offers Commercial Lot, Residential Lot, Industrial Lot, Agricultural, and Raw Land. Historical Commercial/Residential/Industrial labels normalize to the corresponding lot; Farm / Agribusiness normalizes to Agricultural and Logistics to Industrial Lot. Duplicate aliases collapse on restore and save. Asking prices accept positive whole PHP pesos or an explicit Price on request choice; missing prices remain NULL. The primary and additional selectors use the complete server catalog. Restoring a draft rebuilds the classification options before selecting values, excludes stale tags, and requires correction of an invalid historical type/classification combination before continuing.

Classification checkboxes support native keyboard selection. A separate additional-classifications picker is no longer shown. Basics and Location & boundary both offer square meters and hectares and preserve the same physical area on unit changes. Optional contact details accept four additional phone numbers and four labelled social-account or website links, validated on both browser and server, persisted in the existing contact JSON, and restored on edit. Existing contact-access permissions apply.

Draft details autosave after changes, scoped to the signed-in user and listing. Photos, supporting records, and authority files use IndexedDB; the status distinguishes unsaved changes from successful storage. Save & exit keeps the form open when browser storage cannot preserve selected files. File restoration cannot overwrite newer file selections. Submission removes local draft details and media, including after the dialog closes; closing does not recreate a submitted draft. Validation appears beside the affected input and at the top of the editor. Server errors return to the relevant step and focus the field without losing entered details.

Make cover applies to both saved images and newly selected files; the visible gallery, preview, draft, and submitted cover selector agree. The API resolves an uploaded cover index to its server-staged image and validates existing cover IDs against the same property's retained media. Media ordering and the property's image URL stay consistent. Removing the visible cover removes that specific image and falls back to the next image.

Area & location opens with a map for new listings and offers three choices: place a property pin, enter an area size, or draw a plot. Existing area-only drafts keep their selected method. A positive area OR valid latitude and longitude is sufficient; both can also be provided. Barangay is optional. Searching or selecting a barangay moves the map to its approximate local reference, including when a property pin already exists, and never changes that pin's coordinates. Exact names and Brgy/Baranggay aliases resolve locally; partial names show choices instead of selecting the first match. Address results are navigation references; existing listing results identify their recorded pins. Local reference coordinates are not surveyed barangay centers or official boundaries.

Coordinate entry accepts decimal pairs, detectable longitude/latitude reversal, and complete N/S/E/W or DMS notation. Invalid ranges, contradictory hemispheres, and invalid minutes/seconds are rejected. Pasting into the search or either coordinate field updates both coordinates; the pair field supports Apply coordinates or Enter. Six decimal places are retained, with the appropriate hemisphere shown. Pending pair entry is validated before leaving this step. Device location is requested only by its button and shows the browser's estimated accuracy and an accuracy circle; it must be checked against the property. Recenter returns to the current pin; Clear pin removes coordinates without removing recorded area or the boundary. Searching never silently overwrites an existing pin. Closing the form cancels pending search and prevents stale location callbacks from updating another draft.

Drawing uses locally bundled Leaflet-Geoman 2.18.0 and Turf 7.2.0; staff can draw, edit, undo, and reset one closed parcel polygon. The server independently validates the simple WGS84 polygon and recalculates its square-meter estimate.

Apply coordinates selects Map pin, centers on the applied position, and brings the map into view. A previously drawn or restored boundary is preserved and cannot override this camera action. Recenter also targets the pin; selecting Plot boundary explicitly frames the retained plot. Editing or leaving a numeric coordinate field keeps any pending coordinate pair intact until Apply. When a pair is present, Apply uses that pair ahead of the separate numeric fields.

Run `node tests/property-map-navigation.test.cjs` for the production coordinate/camera regression checks, including a saved boundary, numeric-field blur, map visibility, and deferred sizing. Browser verification must check the resulting map center and visible pin with a drawn or restored boundary under normal motion, rather than checking coordinate field values alone.

Both maps open on Satellite, with Streets available in the Map view selector. San Fernando imagery is requested through native zoom 18 and enlarged for map zoom 19; high-density displays do not request another zoom level. Esri requests use [`blankTile=false`](https://developers.arcgis.com/rest/services-reference/enterprise/map-tile/) so missing coverage returns an error instead of its gray placeholder image. Missing imagery falls back to streets, and unavailable OpenStreetMap tiles fall back to Esri streets. A complete provider outage displays coordinate/area guidance. Base-map recovery preserves the pin and parcel geometry; it does not change the availability of hazard evidence.

Manually entered area is labeled Declared area or Survey / property record using `parcel.areaMethod`. It remains separate from `parcel.estimatedAreaSqm`; the entered area takes precedence in preview, review, pricing, and assessment when both exist. Switching square meters and hectares converts the value while preserving the physical measurement. The historical `parcel.surveyAreaSqm` key stores the entered measurement to two decimal places. Public hectare values and calculations use that exact parcel measurement rather than the legacy four-decimal hectare column. For example, 1.49 m² and PHP 1,490 produce PHP 1,000/m², rather than using a rounded 1 m² denominator. The supported minimum is 0.5 m² (0.00005 ha); overflow and values outside the existing database range reject clearly. Unknown coordinates and unknown area remain database NULL and are returned as NULL, with `hasExactLocation` and `areaKnown` flags. Price per m² is unavailable without area; BIR reference total remains pending until area is known. Area-only listings retain pending spatial assessment.

Site evidence and Surroundings are optional. Review listing goes directly to Review after the essentials are valid. The six-criterion editor opens one criterion at a time; supporting records expand on demand. Review shows the listing details and area/location with direct edit actions. A surroundings reference point is not required for submission; when the radar is used, it can derive its reference from the property pin or a drawn parcel. A pin-based hazard result covers that point only, not an unrecorded parcel footprint.

Road frontage, surface, utilities, dated BIR references, environmental references, and site observations are recorded facts. They do not replace authoritative source evidence or approved scoring rules. The current provisional criterion weights are 25/25/20/15/15 for spatial accessibility, infrastructure, economic viability, nearby businesses, and risk. CLUP is a mandatory eligibility gate with no numerical weight. Each missing criterion has a concrete next action. Land-use and CLUP references continue using the existing property fields.

Saved utility statuses, providers, technologies, quality, and measured speed restore from the server's nested records. Internet speed accepts 0 to 10,000 Mbps to one decimal place; clearing it removes the saved measurement. Conditional connection fields retain their draft values while inactive but do not block validation or submit stale measurements. Validation opens the matching utility tab and focuses the field, including when the site editor was collapsed. Unknown answers and coordinates alone do not count as site evidence.

Evidence files accept up to four total JPG, PNG, WEBP, or PDF attachments, each at most 5 MB. The server screens actual MIME, size, signatures, and basic file structure. Images receive additional decoding checks if GD is installed; structural checks are not a complete document or image parser. Files are stored privately under `data/property-evidence`. Staff download them through `api/property-evidence.php`, which checks the property and attachment ID. Public, investor, and broker property responses omit attachment metadata, including save and archive responses. New staged files are discarded if persistence fails before commit. Stored attachment paths cannot be supplied by the browser.

`api/parcel-context.php` exposes configured, verified and fingerprint-checked flood, fault, and road geometry. Missing data displays **Not assessed**. Whole-parcel flood intersection and fault-buffer intersection use Turf. The configuration in `app/assessment-sources.php` must provide verified sources and their coverage, source reference, and date. Set `parcel_context.fault_buffer.meters`, `approved: true`, and the office's `approval_reference` only after the review threshold is approved. A no-overlap finding requires complete source coverage containing the entire parcel. It is not an official clearance.

The surroundings radar stores a labeled reference point. Property location follows the current pin; parcel center follows the drawn boundary; an independently placed entrance stays independent. Moving the property pin refreshes its radar reference. Distinct mapped records are filtered within 500 meters of the exact requested coordinates, including cached results. Duplicate records are removed; closed businesses are excluded and unknown operating status remains unknown. Road distance uses the nearest line segment, including roads crossing the circle whose endpoints lie outside it. Competitor and complementary roles use the selected business type; other mapped places remain separately counted.

Observed business density = unique mapped business count / (π × (radius meters / 1,000)²). A 500-meter search covers about 0.7854 km². Civic amenities and road segments do not count as businesses. The API returns observed count and density separately from a complete inventory, which remains unknown; successful OpenStreetMap retrieval does not establish complete coverage. A zero observed count is not proof that no businesses exist. Provider failures, cached fallback, and partial local coverage remain visible. Nearby directories also retain distinct neighboring merchants and actual source/status metadata. Proximity does not establish demand or legal road access.

Review has assessment and investor preview tabs. Approved, complete business profiles can produce up to three eligible business fit results, with criterion ratings, weights, reasons, and concerns. The shipped profiles and authoritative assessment sources are unapproved/unconfigured, so real scores and business matches remain pending. See [business preview configuration](property-business-preview.md). Illustration scores from the reference screenshots are not saved as city evidence.

The property-details opportunities module also uses measured, deduplicated records and observed business density. Empty or unlocated properties do not fall back to demonstration recommendations or fabricated map anchors. Demonstration content is available only through an explicit, visibly labeled demo option.

The property details page uses Inter body text and a red italic Poppins property heading. Both fonts are loaded locally for the property interface and printed report; Poppins SemiBold Italic is distributed under the included `assets/fonts/poppins-OFL.txt` license. Overview, contact, location, and score summaries appear first; detailed evidence and calculations expand on demand. Printing expands all report disclosures, includes property information and source evidence, and restores the previous screen state afterward. The report shows each MCE rating × weight ÷ 100 contribution, the single weighted IAI rounded once to one decimal. Pending criteria remain pending and prevent totals. Proposed-business incentive adjustments are separate from this base IAI.

Availability choices include Available, Unavailable, Reserved, Sold, and Leased. Availed is retained for historical records; new transactions use Sold or Leased. Delete moves a listing to Recently deleted and retains its evidence, inquiries, due diligence, and audit history. Restore preserves its availability, moderation, and archive state. Public listing visibility remains governed by the existing server permissions and lifecycle rules. Brokers can archive their own listings; administrative deletion and restoration require city management permission.

Validation includes `tests/property-lifecycle.test.php --integration`, `tests/parcel-wizard.test.php --integration`, `tests/assessment-persistence.test.php --integration`, `tests/property-evidence.test.php`, `tests/property-business-profiles.test.php`, `tests/automatic-assessment-ui.test.cjs`, and `tests/property-details.test.cjs`. Integration checks use isolated temporary MySQL databases. Browser QA exercises both roles, area-only and location-only submissions, validation, drawing, existing parcels, shared FormData fields, printing, and mobile layouts without creating catalogue listings.

Focused regression suites cover shared classification and restored tags (`property-classification.test.php`, `property-wizard-classification.test.cjs`), numeric inputs and exact area (`property-wizard-inputs.test.cjs`, `workspace-area-input.test.cjs`, `property-numeric-precision.test.php`), radius/density and nearby data integrity (`surroundings-density.test.php`, `nearby-businesses-integrity.test.php`, `business-opportunities-observed.test.cjs`), and draft/media cover handling (`property-wizard-draft-photos.test.cjs`, `property-media-cover.test.php`). Media-cover tests use SQLite in memory. Current browser results and screenshots are in `.ui-audit/wizard-overhaul/`, including real local endpoint reads and intercepted write requests validated by isolated production PHP.

## Focused assessment and edit history

The assessment workspace uses a desktop section sidebar and a mobile section selector. Cost & Market has two short sections: Your property and Similar property. Asking price/rent is reused from Basic information with a Change price action; the visible inputs are space offered, floor area when relevant, and the comparable rate. Land area is reused automatically. Building records without an explicit saved space scope initially select Whole building; existing saved selections and device drafts are preserved. Monthly total rent is labeled separately from rent per m²/month. The live result sits beside the inputs on desktop and follows the comparison on mobile, showing the difference, provisional score, contribution and missing inputs. Comparison source, upfront terms, tax references and scoring details expand separately. Optional terms do not change the score; no benchmark is invented. Annual rent is converted to monthly rent; daily rent has no assumed monthly basis. Sale-or-lease offers can use a documented lease benchmark when a sale comparison is unavailable, with matching units on the PHP evaluator. These calculations measure property price competitiveness, not business profitability.

An incomplete Cost & Market row shows the specific blocker in Review and in the live result. Recorded/drawn land-area discrepancies above 25% display both areas and their percentage difference as Check area; missing price, floor area, comparable rate or unsupported rent period have their own messages. The action opens and focuses the relevant field, including Location & boundary for a survey discrepancy, on desktop and mobile. No geometry or survey measurement is changed automatically. Reconciling the inputs recomputes the criterion immediately; correcting one field may reveal another outstanding requirement. The saved PHP preview also retains the discrepancy in its missing requirements.

Risk uses six source-classification selectors. Scores and contributions update on change; numeric zero remains zero suitability. Missing or unknown hazards never become no exposure. Contributions and aggregate calculations retain the full weighted result until display rounding. High and critical hazards retain a technical review hold regardless of the average. Saved observations restore into their selectors; clearing a finding clears the saved canonical observation.

The assessment sidebar uses plain section names and shows the current section separately from the four main form steps. On smaller screens, a section selector replaces the sidebar. Risk opens directly to the six reported findings and their recorded count. Scoring columns and the scorecard appear when Scoring & calculation details is expanded; elevated-hazard alerts remain visible while it is closed. Location, source documents, bulk entry and site notes expand separately. Zoning opens with two short sections for property zoning and the proposed business. District descriptions, suggestions and activity search are available through help disclosures; location and clearance documents expand separately. The fixed footer provides Back, Save draft and the next section action. The source and scoring rules, field names and stored data are unchanged. Browser verification of the shared staff and broker templates, keyboard navigation, drafts, critical and unknown findings, and 320/390/768/1024/1536-pixel layouts is recorded in `.ui-audit/assessment-simplicity/`.

Nearby businesses immediately reports deduplicated business count, observed businesses per km², direct competitors, and complementary places. Schools and other civic amenities are excluded from business density. When certified BPLO benchmarks are unavailable, the server calculates an explicitly provisional screening score (`nearby-observed-screening-v1`) from the 500 m observations. Activity is `min(businesses / 20, 1) × 100`; complementary support is `min(non-anchor complementary places / 5, 1) × 100`; competition is `(1 − competitors / businesses) × 100`; anchors are `min(anchors / 3, 1) × 100`. Subcriteria weights are 25/30/30/15%; the criterion contributes `score × 0.15`. Anchors and other complementary places are disjoint. These operational reference counts await city calibration; this model does not establish demand or profitability. Empty business inventories remain pending. The formula and caveat appear in the editor, and Review labels the result Provisional. Certified scoring and final IAI retain their existing evidence gates.

The versioned observations, business profile, source, radius and reference coordinates persist in `parcel.observations.nearby_screening`, including device drafts. PHP validates the counts and recomputes the score on save; client score or verification flags cannot authenticate it. It remains separate from the authoritative `nearby_businesses` aggregate. Reopening restores the preview, while a changed reference or business profile invalidates it until a matching scan is available. Local results display first, with separately bounded live enrichment as described below. Local coverage remains incomplete and does not claim live road coverage.

CLUP offers an optional exact district–activity screening check against the embedded PHP rules. Generic allowed/prohibited confirmation cannot replace that rule lookup, and missing rules stay undetermined. It adds no points. The listing may still be saved without a proposed activity; official clearance remains separate. Review initially shows the property summary and submission action, with location checks and detailed assessment expanded on request.

Completed input calculations are also presented as a separate provisional total in Review and on the staff listing cards. `PropertyScreening::fromProperty()` recomputes the five criterion scores from saved parcel observations and financial terms during repository hydration; existing completed listings need no migration or bulk rewrite. `screeningAssessment` is explanatory and never replaces `iaiScore`, `mceScore`, evidence verification or ranking eligibility. The sum uses 25/25/20/15/15 weights, preserves intermediate precision and rounds once to one decimal. Cost preview uses the shared pricing rubric with an explicit `preview_only` option: missing source authentication does not prevent this provisional calculation, but absent benchmarks, incompatible units, implausible measurements and survey/boundary discrepancies still do. The default authoritative evaluator keeps its verification requirements.

Cards show one assessment result with a Provisional label, or actual criterion progress and the next missing input. Critical hazard findings, prohibited zoning and out-of-coverage locations explain the hold. Five numerical criteria can be displayed with a Zoning pending label while the activity/district check is outstanding; this does not establish clearance. Current verified IAI takes precedence. View assessment opens the existing editor directly at the expanded assessment review. The staff publication review dialog uses the same result and five-row weighted calculation; it no longer assumes an 85-point baseline or treats unavailable hazard layers as a passed screening. Embedded CLUP lookup statuses are translated to the same gate values as PHP (100/70/0 for permitted/conditional/prohibited), without adding any weight or claiming source authentication.

Undo and Redo keep up to 60 in-memory snapshots of property fields, classifications, area, location, parcel boundary, and listing photos, with Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y shortcuts. History resets for another listing. Draft persistence remains separate; supporting document file inputs use the existing draft-file workflow. Out-of-coverage coordinates show a persistent correction/clear-pin action while retaining declared area. The extent is the shared conservative map coverage rectangle, not an official municipal boundary determination. Map layers and radius rings are cleared when switching listings, and modal maps avoid zoom callbacks into removed geometry.

Verification: `node tests/property-editor-calculations.test.cjs`, `node tests/property-wizard-computation-parity.test.cjs`, the step-3 PHP/JS suites, classification and coordinate suites, and isolated parcel/persistence checks. Browser QA renders the actual admin/broker templates and scripts, intercepts property writes, and uses synthetic API responses for deterministic arithmetic, slow nearby responses, saved-property restoration, undo/redo, and mobile layout checks. External map-tile availability is independently dependent on the providers/network.

Staff listing cards keep property details, assessment progress, and listing actions in separate areas using the existing navy, burgundy, and gold palette. The five progress segments represent the actual saved criterion results (including zero scores); verified IAI fills all five segments. Incomplete assessments use a compact completion count rather than a score, and Continue assessment opens the first unfinished criterion. Provisional, verified, and held results retain their distinct labels and existing computation rules. Review and Edit details remain separate actions. Mobile cards stack the assessment panel and keep the Manage menu within the viewport, including at 320 pixels.

## Nearby loading and map recovery

The nearby editor first requests `competitors.php` with the exact latitude, longitude, radius, business type, and `source=local`. This path reads and filters the local inventory without contacting Overpass or overwriting live-provider caches. Local results render before `source=live` enriches them. Requests are bounded to 4 seconds for local records and 9 seconds for live enrichment, including response-body parsing. The deadline rejects even if a transport ignores cancellation. Repeated tab selection reuses the current request; changing location, disabling radar, or closing the editor cancels the previous operation. A failed refresh retains results for the current location and scenario. A complete outage ends with a Retry action rather than a permanent spinner.

The business list and straight-line distance checks work independently of Leaflet and Turf. All places is the initial results tab, so a property without direct competitors can still show other nearby businesses. Street/satellite tile errors and stalled tile downloads advance through the configured providers, then display a locally generated coordinate grid. The grid retains the actual property pin, 500-meter circle, and business markers; it is explicitly labeled as a coordinate view rather than street imagery. Imagery failure does not block inventory retrieval or imply missing businesses.

`node tests/nearby-loading.test.cjs` executes the production request and list functions against stalled transports, cancellation, duplicate synchronization, malformed data, and missing map libraries. `php tests/surroundings-density.test.php` additionally checks that local searches do not contact a live provider, reuse unrelated cached records, or overwrite live caches. `.ui-audit/nearby-recovery-qa.mjs` exercises the real local nearby API with property writes blocked: local-first results, blocked tiles, missing map libraries, stalled live enrichment, and an entirely stalled transport. Results and screenshots are saved under `.ui-audit/nearby-recovery/`.
